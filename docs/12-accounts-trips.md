# ანგარიშები და შენახული ტურები

Firebase კონფიგურაციის გარეშე საიტი მუშაობს local-only რეჟიმში და შენახული ტურები ამ ბრაუზერში/მოწყობილობაში რჩება. Firebase-ის ჩართვისას ტური უკავშირდება ავტორიზებულ მომხმარებელს.

მომხმარებელს შეუძლია ტურის შენახვა, შესრულებულად მონიშვნა, საჯარო/პირადი რეჟიმი და გაზიარება. ანგარიშის არქონა არ ბლოკავს რუკას, დამგეგმავს ან გაქირავების მოთხოვნას.

Google ავტორიზაციისთვის საჭიროა რეალური Firebase პროექტი, Google provider და authorized domain. credentials არ უნდა გამოიგონოს ან ჩაიწეროს repository-ში.

## „ჩემი ჯავშნები" — ამჟამად არააქტიური

ანგარიშის გვერდზე არსებობს ჯავშნების ბლოკი (`static/auth.js:370`) და ადმინის ჯავშნების კონსოლი (`static/admin-bookings.js:29`). ორივე მხოლოდ **კითხულობს** `bookings` კოლექციას.

`bookings`-ში ჩანაწერს არცერთი კოდი არ ქმნის — ფაზა 1-ში საჯარო ნაკადი სტატიკურ მოთხოვნაზე გადავიდა ([11-rental-inquiry.md](11-rental-inquiry.md)), წერის გზა კი მოიხსნა. შესაბამისად ეს ბლოკები Firebase-ის ჩართვის შემდეგაც ცარიელი დარჩება, ისევე როგორც მათზე დამოკიდებული ვადის გაგრძელება და მანქანის შეფასება.

ეს არქიტექტურული ვალია და არა დასრულებული ფუნქცია — იხილეთ [LOCAL_IMPLEMENTATION_STATUS.md](LOCAL_IMPLEMENTATION_STATUS.md).
