ადმინისტრაციის გამართვა

საიტის ყოველდღიური მართვა ხდება https://თქვენი-დომენი/admin/ მისამართიდან. პაროლი ან OAuth secret რეპოზიტორიაში არ ინახება.

1. საიტის გამოქვეყნება

  1. GitHub-ზე გახსენით ko500pl/car-rental-site და დარწმუნდით, რომ მფლობელს აქვს Write ან Admin წვდომა.
  2. ჰოსტინგზე დაუკავშირეთ ეს რეპოზიტორია.
  3. build command: python build.py dist --strict; publish directory: dist.
  4. strict build არ გაუშვებს საიტს, სანამ რეალური ტელეფონი, ელფოსტა, სოციალური ბმულები და მანქანის მთავარი ფოტოები არ შეივსება.

2. GitHub OAuth

  1. GitHub → Settings → Developer settings → OAuth Apps → New OAuth App.
  2. Homepage URL-ში ჩაწერეთ რეალური დომენი.
  3. callback URL გამოიყენეთ თქვენი ჰოსტინგის OAuth gateway-ის ინსტრუქციის მიხედვით.
  4. Client Secret შეინახეთ მხოლოდ ჰოსტინგის უსაფრთხო პარამეტრებში — არა ფაილებში.
  5. ავტორიზებული რედაქტორი უნდა იყოს GitHub repository collaborator.

3. შესვლა

გახსენით /admin/, დააჭირეთ Login with GitHub და დაადასტურეთ წვდომა. ცალკე „მთავარი ადმინის პაროლი“ ამ არქიტექტურაში არ არსებობს და კოდში არ უნდა ჩაიწეროს.

4. კონტაქტები და ბიზნეს ინფორმაცია

Admin → პარამეტრები → საიტი. აქ იცვლება ბრენდი, ლოგო, დომენი, ტელეფონი, WhatsApp, ელფოსტა, მისამართი, კოორდინატები, სამუშაო საათები და სოციალური ბმულები. WhatsApp ნომერი შეიყვანეთ საერთაშორისო ფორმატით, მხოლოდ ციფრებით.

5. მანქანის დამატება ან შეცვლა

Admin → ავტომობილები → New Automobile. შეავსეთ სტატუსი, კატეგორია, ტექნიკური მონაცემები, ადგილები, ფასები, დეპოზიტი, დაზღვევა/ფრანშიზა, გარბენის ლიმიტი, მინიმალური ვადა და ყველა ექვსი ენა. ახალი ჩანაწერის უსაფრთხო საწყისი სტატუსია draft.

6. ფოტოების ატვირთვა

„მთავარი ფოტო“ გამოიყენება ავტოპარკში, რეკომენდაციასა და სოციალურ გაზიარებაში. რეკომენდებულია 1200×750 WebP/JPG. დამატებითი ფოტოები დაამატეთ Gallery-ში. დაუმთავრებელი გალერეა გატეხილ სურათს არ აჩვენებს.

7. ფასები

მანქანაში შეავსეთ GEL-ის 1–6, 7–29 და 30+ დღის ტარიფები. დოლარი ითვლება ავტომატურად 2.6 კურსით და მრგვალდება 10 დოლარამდე; მანქანაში USD ხელით არ იწერება.

8. გამოქვეყნება და დამალვა

  • draft — საიტზე არ ჩანს;
  • published — ჩანს გვერდებზე, რეკომენდაციაში, sitemap-სა და schema-ში;
  • archived — ინახება ადმინისტრაციაში, საჯაროდ არ ჩანს;
  • „ამჟამად ხელმისაწვდომია“ გამორთვისას გვერდი შეიძლება დარჩეს, მაგრამ დამგეგმავი მას აღარ ურჩევს.

9. გამოქვეყნებამდე შემოწმება

გაუშვით python build.py --validate-only, შემდეგ python build.py dist --strict. შეცდომის ტექსტი მიუთითებს შესავსებ ველს. მხოლოდ წარმატებული strict build არის წარმოებისთვის მზად.
